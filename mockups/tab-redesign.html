↳ Notice: tabs run off the right edge. The "Subs" and "Financials" tabs are invisible without horizontal scroll.

The diagnosis

13 tabs, all the same weight, all the same size. The eye has to scan the entire strip to find anything. On mobile, the last 2-3 tabs are off-screen with a faint fade hint. There's no semantic structure — the user can't tell that "Permits" and "Takeoff" are field operations while "Pay apps" and "Financials" are money.

What's broken specifically

  • No hierarchy — every tab is equal. "AI board" is just as prominent as "Permits".
  • Mobile is hostile — fade-out tells the user there's more, but the icon+label doesn't shrink.
  • No status at a glance — to know "how are we doing on pay apps", the user has to click into Pay apps and read.
  • Tab labels overlap their badges — the "Pay apps 3" label crowds the badge.

// When to keep this

If users always know exactly which tab they want (experts), and the project list is short, this is fine. Otherwise it stops scaling past ~8 tabs.

How it works

Left rail ~240px, fixed, always visible on desktop. 4 groups — Working, Schedule, Money, Site. Active item has orange-tinted background and orange left border. Every item can show a status badge (count, dollar amount, warning dot).

The status-at-a-glance win

The sidebar isn't just navigation — it's a status board. The user opens a project and immediately sees: 3 tasks overdue, 5 on site, $45k AR, 2 AI alerts. They can navigate to any of them in one click.

Mobile

The sidebar collapses to a drawer triggered by a hamburger in the page header. Tap → drawer slides in from the left, takes 80% of the screen, all groups visible, all status badges visible. Tap outside to close.

// Strengths

  • Every section is one click, always
  • Status badges teach the user where attention is needed
  • Scales to 30+ sections without breaking
  • Linear/Notion/Stripe users already know this pattern
  • On mobile, drawer is more discoverable than horizontal scroll

// Tradeoffs

  • Reclaims ~240px of horizontal space on every project page
  • Has to be implemented thoughtfully to not feel like a workspace dashboard in itself
  • Adds a layout change to every project sub-route (photos, pay-apps list, etc.)

How it works

No tab bar. The Overview page IS the hub. Eight cards (4-col desktop, 2-col tablet, 1-col mobile), each with live status, a stat, and a 1-line sub. Click a card → enter that section. Inside each section, in-page tabs handle sub-views (e.g. Pay apps → Drafts / Sent / Paid).

Why this is bold

The current nav is a horizontal list. This turns navigation into a spatial experience — the user looks at the project, sees what's hot, and dives in. It's how Vercel, Linear, and modern dashboards all work. It also gives every feature equal visual real estate (instead of competing for tab-bar pixels).

Why it works for "functionality"

Each card carries a real piece of data. "Draw 8 sent — $45k outstanding" is more useful than a tab labeled "Pay apps". The user knows the state before they click. Status colors (orange = needs attention) guide the eye.

// Strengths

  • Zero learning curve — cards are universal
  • Status at a glance — every card carries a live number
  • Scales infinitely — add a feature, add a card
  • The Overview page becomes a real product surface, not just a project header

// Tradeoffs

  • Loses the persistent nav — clicking Pay apps doesn't feel like "moving"
  • Users who want a sidebar for power-navigation need to add a sub-nav inside sections
  • Biggest build cost — every card needs a real data source

How it works

Pin 6 most-used tabs in the bar (Overview, AI board, Photos, Tasks, Pay apps, Check-in). Everything else lives in a "More" dropdown that opens a clean menu. Smallest change, biggest perceived improvement.

Smart variant: usage-based pinning

Track which tabs each user opens most. After 7 days, "More" auto-hides tabs they use daily, and pinned tabs auto-add ones they use more. So a PM who lives in Subs and Inventory would see those pinned instead of AI board.

// Strengths

  • Ships in 1 day
  • Preserves everything that works — just hides the long tail
  • Mobile gets dramatically better (6 tabs fit, 7 in a clear menu)
  • No layout change to sub-routes

// Tradeoffs

  • Not a "real" redesign — more like a patch
  • Smart pinning adds analytics work
  • Doesn't scale past 13 tabs forever — when you hit 20, you need A or B

How it works

Top row: 5 "Working" tabs (Overview, AI, Photos, Tasks, Team) — bigger, more prominent, with a small `WORKING` label. Bottom row: 8 "Rest" tabs in a calmer style with a `REST` label, on a slightly different background. Both rows scroll horizontally on mobile.

Why this works

Visual hierarchy is immediate. Your eye lands on the top row because it's bigger and on a brighter background. The bottom row is for "the long tail" — you can see everything but it doesn't compete. On mobile, both rows are still scrollable, but the top row is what you reach for first.

// Strengths

  • All 13 visible without hiding anything
  • Hierarchy is clear at a glance
  • ~1.5 day build, similar to C
  • Scales to ~25 tabs before becoming unwieldy

// Tradeoffs

  • Takes 2x the vertical space of a single bar
  • Still horizontal-scroll on mobile
  • The "Rest" label feels a bit apologetic
