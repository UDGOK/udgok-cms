fix: photos lightbox shows Edit/Delete for OWNER/ADMIN, pay app URL, AI labels

Three related bugs the user reported after the previous fix:

1. PHOTOS LIGHTBOX: no Edit or Delete buttons even though the
   user is the workspace OWNER. The page hardcoded
   `canDeleteAny={false}`, so the buttons only showed when
   the signed-in Clerk user matched the photo's uploaderId.
   But the user is signed in as `yasir@udgok.com` while the
   photo was uploaded by `yasir@futonix.com` (two different
   Clerk accounts for the same person). The backend
   `updateProjectPhotoAction` and `deleteProjectPhotoAction`
   both correctly allow OWNER/ADMIN to act on any photo;
   the UI just wasn't surfacing the buttons.

   Fix: read the membership role and pass `canDeleteAny=true`
   for OWNER/ADMIN. PM/ESTIMATOR/FIELD still get the strict
   "only your own photos" behavior.

2. PAY APP BUTTON: clicking "Generate pay app" navigated to
   /w/_/projects/... — workspace slug was an underscore.
   The project page (page.tsx line 1340) was passing the
   workspace OBJECT to a prop typed as `string`. The page
   does `const { workspace } = await requireMembership(...)`
   which returns a workspace object, not a slug, so when
   stringified it became garbage. TypeScript should have
   caught this; the prop type annotation is on the client
   component, not the page, so it slipped through.

   Fix: `workspaceSlug={workspace}` → `workspaceSlug={workspace.slug}`.
   The same pattern in other components on the same page
   already uses `params.workspace` or `workspace.slug`
   correctly, so this was an isolated mistake.

3. AI BOARD: the loading skeleton still said
   "// NVIDIA executive summary" and the insight source
   type was 'nvidia' — leftover from before the OpenRouter
   migration. Now reads "// OpenRouter executive summary"
   and the source discriminator is 'openrouter'. No
   behavior change, just labeling.

4. NEW: /api/admin/ai-health endpoint (master-admin only).
   Returns whether UDGOK_CMS_OPENROUTER_API_KEY is set,
   the model chain, and (with ?live=1) the result of a
   real test call. Use this to verify the Vercel env
   var is wired correctly:

     curl 'https://cms.udgok.com/api/admin/ai-health?live=1' \
          -H "Cookie: $(clerk-session-cookie)"

   This is the fastest way to diagnose "AI not configured"
   vs "AI configured but model is rate-limited" without
   having to read Vercel function logs.
