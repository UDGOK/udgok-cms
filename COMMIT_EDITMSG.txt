feat: project tabs are now consistent + mobile-perfect

USER REQUEST: 'can you also see if the tabs inside the
projects are perfectly visible and aligned like a
perfectionist interior designer will and on mobile they are
mobile friendly and they are consistent on all projects'

DIAGNOSIS

Before this commit, the project nav was inconsistent across
routes:

  - Main project page (page.tsx)        — 12 tabs
  - Photos page (photos/page.tsx)       — 8 tabs
  - Pay apps list (pay-apps/page.tsx)  — 8 tabs
  - Pay app detail (pay-apps/[id])     — NO tabs
  - New pay app (pay-apps/new)         — NO tabs

The dedicated routes were silently dropping 4 tabs
(AI board, Takeoff, Inventory, Map), so a user deep-linking
into /photos had no way to reach AI / Takeoff / Map without
navigating back to the main project page first. That's
the "consistent on all projects" problem.

The main page also hand-rolled its own tab list with
hard-coded badge logic — drift between the two lists was
inevitable.

FIX

  1. NEW: lib/projects/tabs.ts — single source of truth
     for the tab list and badge computation. Exports:
       - getProjectTabs(ctx):  pure config from pre-fetched
         counts. Used by the main page (which already has
         every count from getProjectWithRelations).
       - getProjectTabsFor(ws, pid):  fetches the missing
         counts and calls getProjectTabs. Used by the
         dedicated routes that don't have the data.

  2. UPDATED: ProjectTabsBar is now a 6-line wrapper around
     getProjectTabs(props). The duplicated list + badge
     logic in the old bar is gone.

  3. UPDATED: project main page uses getProjectTabs(...)
     instead of building its own list. The previously
     in-page `permitsBadge` calculation is removed (the
     helper owns it). The permit summary is still computed
     locally because PermitsTab needs it for the actual
     permits list.

  4. UPDATED: pay-app detail and new pay-app pages now
     render the full 12-tab nav and a MobilePageHeader
     (mobile back button + title). These were the worst
     offenders — no nav at all.

  5. UPDATED: ProjectTabs component got the perfectionist
     mobile polish:
       - Edge fade gradients on left + right that appear
         ONLY when (a) the tab row overflows the viewport
         AND (b) the user hasn't scrolled to that edge.
         So desktop never sees them; mobile gets a hint
         that there's more without visual clutter.
       - Active tab auto-scrolls into view on navigation
         (with inline: 'center' so the user can see the
         tab they came from AND the next one — orientation
         cue after a deep link lands off-screen).
       - Larger touch target on mobile: min-h-[36px] vs
         [32px] on desktop. py-2 (8px) on mobile, py-1.5
         (6px) on desktop. Apple's HIG minimum is 44px;
         we're 36px which is acceptable for a horizontal
         scroll nav (vertical thumb scroll is the
         dominant mobile gesture, not tap precision).

  6. TESTS: lib/projects/__tests__/tabs.test.ts — 9
     regression tests covering:
       - 12 tabs in the documented order
       - All tabs have non-empty label + absolute href
       - Badge omitted at 0, shown at > 0
       - Photos badge = ROUGH_IN + FINAL
       - AI badge only on warning/danger count > 0
       - Permits badge prefers overdue over total
       - getProjectTabsFor calls the right Prisma models

     272 → 281 tests passing.

VERIFICATION

  - TypeScript compiles clean (only pre-existing test-file
    errors that don't block next build).
  - The 5 routes that render project sub-nav (main page,
    photos, pay-apps, pay-app detail, new pay-app) all
    render the SAME 12 tabs in the SAME order. Verified
    by reading each page after the change.
