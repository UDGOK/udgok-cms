fix: CSP img-src was missing Vercel Blob domain — uploaded photos blocked

USER REPORT: 'i tried it it diodnt load the image'

ROOT CAUSE

The photo URL returns HTTP 200 with 318733 bytes of valid
JPEG data. So the upload succeeded, the blob is fine, the
DB is fine, the server is fine. The browser is the one
that refuses to display it.

The Content-Security-Policy header in next.config.mjs has
these directives:

  img-src     'self' data: blob: https://clerk.udgok.com
              https://img.clerk.com
              https://*.tile.openstreetmap.org
              (Vercel Blob missing!)

  connect-src 'self' https://clerk.udgok.com
              https://*.tile.openstreetmap.org
              https://nominatim.openstreetmap.org
              https://api.weather.gov
              https://*.public.blob.vercel-storage.com
              https://api.resend.com
              (Vercel Blob present)

When the security audit shipped in the previous session,
I added Vercel Blob to connect-src (for the upload XHR
fetch call) but forgot to add it to img-src (for displaying
the uploaded photo in the gallery).

The image src is
  https://15c4iwiin1qbgxzg.public.blob.vercel-storage.com/...
                          subdomain of public.blob.vercel-storage.com

The browser evaluates img-src, sees no matching origin,
and silently blocks the <img> request. The photo row is in
the DB, the URL is valid, but the user sees a broken image.

This is the entire reason the user reported "i tried it
it diodnt load the image" AFTER the SW fix was deployed.
The SW fix was correct — it was just exposing a SECOND
bug that was always there.

DIAGNOSIS STEPS (in case it happens again)

  1. The URL returns 200 with content. So it is NOT:
     - a Vercel Blob problem (blob has data)
     - a DB problem (row exists, URL is current)
     - a service worker problem (we already fixed that)
  2. The browser DevTools network tab would show the image
     request in red with a CSP error in the console:
     "Refused to load the image ... because it violates
      the following Content Security Policy directive:
      'img-src ...'."
  3. The fix is to add the missing host to img-src.

FIX

  next.config.mjs — add to img-src:
    https://*.public.blob.vercel-storage.com
    https://public.blob.vercel-storage.com
  (Both forms because Vercel Blob URLs include a random
  subdomain prefix; the bare host is included as
  defense-in-depth.)

  Also: refreshed the OpenRouter reference in the header
  comment (it still mentioned NVIDIA NIM, which we
  migrated away from in commit 296eaf8). No behavior
  change from the comment update.

REGRESSION TEST

  Added __tests__/csp.test.ts with 5 tests:
  - img-src allows Vercel Blob (wildcard + bare host)
  - img-src allows Clerk avatars
  - img-src allows OSM tiles
  - img-src and connect-src cover the same Vercel Blob
    domains (the cross-check that would have caught
    the bug originally)

  Verified the test catches the bug: temporarily removing
  the Vercel Blob entries from img-src makes 3 tests fail
  with a clear, actionable error message pointing at
  the exact directive and the missing host.

  279 → 284 tests passing. Build clean.

VERIFICATION

  After deploy, the user just needs to refresh once. The
  new CSP header takes effect on the very next request
  served, and the previously-uploaded photos will
  immediately appear in the gallery (their URLs were
  always valid; only the browser was blocking them).
