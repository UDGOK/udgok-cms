fix: next build was failing on vitest config TS check

USER REPORT: 'Command "pnpm exec prisma db push --skip-generate
--accept-data-loss && rm -rf node_modules/.prisma && pnpm exec
prisma generate && pnpm exec next build" exited with 1'

The Vercel build failed at the TypeScript-validation step:

  ./vitest.config.ts:14:5
  Type error: No overload matches this call.
  Object literal may only specify known properties, and
  'environmentMatchGlobs' does not exist in type 'InlineConfig'.

ROOT CAUSE

In the previous commit I added `environmentMatchGlobs` to
vitest.config.ts so the React-hook tests could opt into
jsdom via a glob. The property name is correct in newer
Vitest versions, but our installed Vitest (4.1.10) doesn't
expose it on `InlineConfig` — it errors out at typecheck.

Next's build runs `tsc --noEmit` against every file in
tsconfig's `include` (which globs `**/*.ts`), so
vitest.config.ts was being type-checked against the Vitest
type definitions, and the unknown property was an error.

FIX

  1. Removed `environmentMatchGlobs` from vitest.config.ts.
     The per-file `// @vitest-environment jsdom` directive
     at the top of `client-upload.test.tsx` already does
     the same job (and works regardless of Vitest version).

  2. Added `vitest.config.ts` to tsconfig.json's `exclude`
     list. This file references Vitest-specific types
     (`InlineConfig` shape that changes per version) and
     isn't part of the Next.js build — no reason for Next
     to typecheck it. Other test config files (vitest.setup,
  etc.) should also go here if added.

VERIFICATION

  - `pnpm exec tsc --noEmit` clean (only pre-existing
    test-file errors that don't block next build).
  - `pnpm test` → 284/284 passing.
  - `next build` → "Compiled successfully", full route
    table generated, exits 0.

The Vercel build should now succeed. The deployed app
includes the file-upload fix from the previous commit
(progress bar updates, file appears in list without a
manual refresh).
