4Tighten CSP — nonce-based script-src

Currently script-src 'unsafe-inline' 'unsafe-eval' https://clerk.udgok.com. On the deployed build we don't need 'unsafe-eval'. Switching to a per-request nonce is a documented Next.js pattern.

// next.config.mjs — current "script-src 'self' 'unsafe-inline' 'unsafe-eval' https://clerk.udgok.com" // next.config.mjs — proposed async headers() { const nonce = ... return [{ source: "/(.*)", headers: [{ key: "Content-Security-Policy", value: `script-src 'self' 'nonce-${nonce}' https://clerk.udgok.com`, }], }]; }

Next.js 13.4+ ships nonce-based CSP for App Router. Drops 'unsafe-inline', 'unsafe-eval', and tightens the XSS surface. The __tests__/csp.test.ts file already exists and would catch any new domain added without an img-src entry — extend it to verify the new nonce pattern.

Effort: ~ 3–4 h · Risk: low (test in staging first) · Rollback: revert header
